The Documenso e-signature flow (send lease → both parties sign → document seals → our DB records SIGNED + stores signed PDF) had **three stacked infrastructure bugs**, none ever exercised until the first real end-to-end lease-signing test on 2026-07-13 (session 42). Each one alone silently broke completion; all three now fixed and verified end-to-end (lease `d262309d-...`, Documenso doc id 10, tenant Hugh Smith on Apt C1).

1. **No signing certificate.** Documenso's `internal.seal-document` background job failed with `ENOENT: no such file or directory, open './example/cert.p12'` — the container was never given a PKCS#12 signing cert, so documents stayed at "all recipients signed" but never flipped to COMPLETED. Fix: generated a self-signed cert on the VM (`openssl req -x509 ... | openssl pkcs12 -export`), stored at `/opt/jag/jag-infra/documenso/cert.p12` (chmod 600, volume-mounted, NOT baked in image), wired `NEXT_PRIVATE_SIGNING_TRANSPORT=local` + `NEXT_PRIVATE_SIGNING_LOCAL_FILE_PATH=/opt/documenso/cert.p12` + `NEXT_PRIVATE_SIGNING_PASSPHRASE=${DOCUMENSO_SIGNING_PASSPHRASE}` into `docker-compose.yml`'s documenso service + `.env`. Self-signed is standard for self-hosted Documenso (no public CA needed for internal doc-sealing). Seal job runs on a `*/15 * * * *` cron sweep, so an already-signed doc completes within 15 min of the cert being present.

2. **`jag-signed-documents` bucket missing from the MinIO IAM policy.** The webhook stores the signed PDF into `BUCKET_SIGNED_DOCUMENTS` (`jag-signed-documents`), but the `jag-app-buckets` policy (`scripts/setup-minio-policy.sh`) only listed 4 buckets — this 5th one was referenced in code but never authorized. `putObject` failed with MinIO's `"Valid and authorized credentials required"` (that string == S3 AccessDenied, NOT a Documenso/API auth problem — easy to misread). Fix: `mc mb jag-signed-documents` + added it to both Resource arrays in `setup-minio-policy.sh` (re-ran the script). See [[project-secrets-and-env]] for the 4-bucket policy background.

3. **Webhook body rejected as too large → empty `req.body` → silent drop.** Documenso's `DOCUMENT_COMPLETED` webhook embeds the **full base64-encoded signed PDF** in the JSON payload (~416kb for a 12-page lease). The global `express.json()` default 100kb limit rejected it, leaving `req.body` empty; the handler read `documentId=''` and hit a silent `if (!documentId) return`, so our record never updated. Documenso's own `WebhookCall` log showed `200 SUCCESS` (because the handler acks 200 before touching the body), masking the failure completely. Fix: mount the documenso webhook with its own `express.json({ limit: '10mb' })` **before** the global 100kb parser in `index.ts` (same "mount before global json" pattern as WhatsApp/WiPay, but for size not raw-HMAC reasons); made the empty-body case log `WEBHOOK_EMPTY_BODY` instead of returning silently.

**Diagnostic pattern that worked:** to test this webhook without a fresh real signing, POST a synthetic `{event:'DOCUMENT_COMPLETED', data:{id, status:'COMPLETED'}}` with the real `X-Documenso-Secret` header from inside the container (`docker exec jag-api node -e`), and to test the size fix specifically, pad the body past 100kb with a filler field and send it through the **public** `https://api.jagcorporate.com/internal/documenso-webhook` URL (exercises Caddy + real limits). Re-processing is idempotent (re-stores PDF, re-sets SIGNED). Cross-checked against Documenso's own state via `GET /api/v2-beta/document/:id` (status + per-recipient signingStatus) and the `WebhookCall` table (`responseCode`) in the `documenso` DB.

**Lesson:** a "200 SUCCESS" on the sender's side proves the endpoint ack'd, NOT that it did the work — fire-and-forget handlers that ack before processing hide every downstream failure. Same silent-drop class as the WhatsApp inbound webhook ([[project-whatsapp-inbound-webhook-fix]]) and the MinIO presign gap ([[feedback-minio-presign-public-endpoint]]): a feature "documented as done" that had never actually run end-to-end. Related: [[project-esignature-documenso]], [[feedback-docker-compose-env-wiring-gap]].

**Follow-up (session 43, same day):** the first real end-to-end signing test this pipeline unblocked immediately surfaced 5 more bugs in the actual PDF/signing UX (wrong MinIO bucket on download, field geometry, missing timezone, missing page numbers, footer doubling page count) — see [[project-lease-pdf-rendering-fixes]].
